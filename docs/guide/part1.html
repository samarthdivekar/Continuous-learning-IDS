1 · The project in one page

In one sentence: a network intrusion detection system that looks at traffic as a graph of computers talking to each other, keeps learning new kinds of attack without forgetting the old ones, notices by itself when traffic has changed, and turns thousands of alerts into a handful of explained incidents that a human approves or rejects.

The problem in plain words

Companies watch their network traffic for attacks. Most machine-learning detectors are trained once on a fixed dataset and then frozen. Three things go wrong in practice:

  1. New attacks appear. A detector trained in January has never seen the attack that arrives in March.
  2. Retraining makes it forget. If you train the model again on only the new attack, it forgets the old ones. This is called catastrophic forgetting, and it is dramatic: in this project a normally retrained graph model went from catching 100 % of the first attack type to 0 %.
  3. Analysts drown. A per-flow detector raises one alert per network conversation. A single scan can produce 5,000 alerts in a few seconds. Studies of real security teams describe most of their alerts as false positives (Alahmadi et al., USENIX Security 2022).

What we built

DetectorAn E-GraphSAGE graph neural network that classifies every network flow using both the flow's own numbers and what the two computers involved are doing with everyone else.
Learning over timeContinual learning: new attack types are learned one after another. Two tools stop forgetting: replay (keep a few old examples and rehearse them) and EWC (protect the parts of the model that mattered for old attacks).
Noticing changeAn ADWIN drift detector watches the model's error rate and triggers retraining only when traffic really changes.
Usable outputAlerts are grouped into incidents, each with an explanation, an "I'm not sure" abstention, a novelty flag for unfamiliar traffic, and a proposed firewall rule that is never executed (dry run only).
ConsoleA nine-page web console (Overview, Incident queue, Live sites, Models, Adaptation & trust, Drift replay, Reproducibility, Graph explorer, Classify) served by a FastAPI backend, with sensors, a live model that learns under a safety gate, and a self-contained cyber range.
ProofEvery number comes from scripts in experiments/, run on two public datasets, with multiple random seeds, a realistic time-ordered test split, statistics, 120 automated tests and a browser smoke test.

2 · Scope: what it is, what it is not, and who it is for

What it is

A research prototype of a standalone, flow-based intrusion detector with an analyst console: sensors capture traffic, a graph model scores it, groups alerts into incidents, abstains when unsure, and learns new attacks and the local network from analyst labels under a safety gate, helping a small security team decide what to look at first. It is built so that every claim can be checked: the experiments, the console and the documentation all read the same result files.

What is in scope

  • Classifying network flows (benign, or one of seven attack categories) from 83 flow features.
  • Learning attack categories one after another without forgetting (continual learning).
  • Detecting when traffic changes and deciding when to retrain (drift detection).
  • Detecting attack types the model was never trained on (unseen attacks, novelty).
  • Reducing analyst workload: incidents, explanations, abstention, proposed (never executed) responses.
  • An honest evaluation: two datasets, multiple seeds, a time-ordered split, statistics, failure cases.
  • A working console and API that a person can use and demonstrate.

What is deliberately out of scope

  • Blocking traffic automatically. Nothing ever executes a firewall rule; every action is a dry run.
  • Replacing a SOC platform. There is no case management, no correlation across log sources, no TLS, no user roles. The README and the positioning note say so plainly.
  • Reading packet contents. Only flow statistics (sizes, timings, flags) are used, never payloads.
  • Integrating with other security tools. It does not read other IDSs' alerts (Suricata, Snort, Zeek); it only exports incidents as CEF text for a SIEM.
  • Production validation. All results come from two public laboratory datasets.

Target audience

WhoWhat they get from it
Primary user: a small security team (2–5 analysts) that can place a sensor on its network and wants a behaviour-based second opinion beside its existing defences.Incidents instead of raw alerts, a reason for each one, an "unsure" bucket, a flag for unfamiliar traffic, and a model that keeps up with new attacks.
Examiners and reviewersA system whose every number can be regenerated with one command, with the negative results reported next to the positive ones.

Positioning in one line (from docs/positioning.md): a standalone, flow-based detector with an analyst console that learns new attacks under a safety gate; not a SOC platform.

3 · The real-world problem, with examples

Example 1: the port scan that looks innocent one connection at a time

An attacker's computer (172.16.0.1) tries to connect to 996 different ports on one server in seven seconds. Each single connection is tiny and looks like a normal failed request. A detector that judges one flow at a time sees 4,986 boring flows. A detector that looks at the graph sees one computer reaching out to almost a thousand ports on the same victim: an unmistakable scan. This exact case appears in the Incident queue screenshot in section 10.

Example 2: the detector that forgets

Monday the model learns BruteForce (password guessing). Wednesday it is retrained on DoS (denial of service). On Thursday BruteForce comes back, and the retrained model no longer recognises it. In this project's measurements a normally retrained graph model catches 0 % of the first attack after learning the later ones, while the continual model still catches 99.8–100 %.

Example 3: the attack nobody trained on

A new botnet appears. No labelled examples exist yet. A per-flow model has never seen anything like it and calls it benign. A graph model can still notice that one host is talking to many others in an unusual pattern. On CSE-CIC-IDS2018 the per-flow model detected at most 0.07 % of any never-seen attack; the graph model detected more than 80 % in half of the tests.

Example 4: 100,000 alerts

On the CIC-IDS2017 test traffic, the model flagged about 100,000 flows. Grouping flows that belong to the same attacker and victim turned that into about 50 incidents, 84 % of them real attacks. An analyst can read 50 incidents in a shift; nobody can read 100,000 alerts.

Example 5: traffic changes

Software updates, new users and new attacks change what "normal" looks like. Retraining every day wastes effort; never retraining lets accuracy rot. In this project a model that never adapts falls to 0.230 macro-F1 on the stream, while adapting keeps it around 0.96.

4 · The ideas you need, explained simply

Network flow

One conversation between two computers, summarised as numbers: how long it lasted, how many packets went each way, how many bytes, which TCP flags were set, the time between packets, and so on. CICFlowMeter turns raw traffic into these rows. This project uses 83 numeric features per flow. IP addresses are never used as features; they only decide who is connected to whom in the graph.

Intrusion detection system (IDS)

Software that watches traffic for attacks. Signature IDSs (Snort, Suricata) match known patterns: precise, but blind to anything new. Machine-learning IDSs learn patterns from labelled examples: they can generalise, but they are usually trained once and frozen.

Graph

Dots and lines. Here every computer (IP address) is a dot (node) and every flow is a line (edge) between two dots. Each graph holds 5,000 consecutive flows, called a window.

Attacks have shapes. A per-flow model sees only one line at a time; a graph model sees the shape.

Graph neural network (GNN), E-GraphSAGE

A neural network that works on graphs. For each flow it looks at the flow's own numbers, then gathers summaries of the neighbouring flows (other flows of the same two computers), and combines both to decide. GraphSAGE (Hamilton et al., 2017) introduced this "sample and aggregate" idea; E-GraphSAGE (Lo et al., 2022) adapted it so that the edges (flows) carry the features and get classified. Our model has 69,128 learnable numbers (parameters) and takes milliseconds per window.

Continual learning and catastrophic forgetting

Learning tasks one after another, like a student taking one subject per term. A normal neural network that studies the new subject overwrites what it knew about the old one: catastrophic forgetting. Two cures are used here:

  • Replay (Rolnick et al., 2019): keep a small box of old flashcards and mix a few into every study session. Here the box holds up to 10 old traffic windows per attack type, and two are rehearsed at each training step.
  • EWC, Elastic Weight Consolidation (Kirkpatrick et al., 2017): measure which knobs inside the model mattered most for the old subject, and make those knobs stiff, so learning the new subject moves them as little as possible.

Concept drift and ADWIN

Drift means the traffic the model sees has changed since it was trained. ADWIN (Bifet & Gavaldà, 2007) keeps a window of recent error values and constantly asks: "is the older half of this window significantly different from the newer half?" If yes, it raises a drift flag and the model retrains on the most recent traffic. It is a smoke alarm for accuracy.

Metrics

  • Macro-F1: detection quality averaged over every category, so a rare attack counts as much as a common one. 1.0 is perfect.
  • Retention: how much of the first attack type is still caught after learning all the others. 1.0 = nothing forgotten.
  • False-positive rate (FPR): share of normal traffic wrongly flagged. 0.07 % means 7 false alarms per 10,000 normal flows.
  • BWT (backward transfer): how much older tasks got worse after later training; near 0 is good, negative is forgetting.

Conformal prediction (abstaining)

A way to let the model say "I'm not sure". For each class it learns, on validation data, how low the model's confidence can be for genuine members of that class. If a new flow fits more than one class, or none, the model abstains and hands it to an analyst (Angelopoulos & Bates, 2021).

Calibration

Whether "90 % confident" really means "right 90 % of the time" (Guo et al., 2017). Measured with expected calibration error (ECE).

Open-set / novelty detection

Scoring how unfamiliar a flow looks, so that never-seen attacks can be flagged as "new" rather than forced into a known class. Three scores are compared: maximum softmax probability (Hendrycks & Gimpel), energy (Liu et al., 2020) and distance to class prototypes.

6 · The gap: what was missing, and what this project does about it

Each line of work above solves one piece. In the papers reviewed here we did not find one system that does all of the pieces together and evaluates them with a time-ordered split, several seeds and statistics. That combination, and the honesty of the evaluation, is what this project contributes. It is a combination of known techniques, not a new algorithm, and should be presented that way.

What we do not claim

  • That the graph model is always better: on attacks it has seen, the gain is small (+0.04) and the per-flow model has a lower false-positive rate on one split.
  • That unseen-attack detection is reliable for every attack: BruteForce and Botnet are unstable across three seeds (DoS, however, is detected at 98.6 % on all three).
  • That ADWIN saves retraining: on CIC-IDS2017 it retrains about twice as often as a fixed schedule.
  • That lab results transfer to a real network: both datasets are laboratory captures.
